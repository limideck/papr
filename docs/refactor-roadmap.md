## B. 标签管理专项（里程碑之后续做）

### B1 UI（承接 docs/tag-management-design.md P3/P4）
- **批量模式**：多选节点 → 批量合并/设父/设类型/屏蔽/删除（需后端 batch 端点）

### B2 数据治理节奏（长期）
- 每 30 天：快照 → `papr tag tidy` 干跑 → 人工审计划 → apply（本地副本流程已具备，产物=plan JSON+diff）
- 一次性/低频策略：**只在“人工审核队列”里存活**，超期未审自动清理（见 C）
- 词表实体(中英同义词)更新 → 重导 meili synonyms（自动化：hash 变化触发）

### B3 L1 领域层（v35 机制已落地；**扩展与数据已按架构评审搁置**，详见 E）
- **现状（2026-09 已落地）**：`tags.domain` 可空列（v35）+ 6 域枚举 `Economy / Finance / National Security / Geopolitics / Technology / Society`；`GET /api/tags/{id}` 与 hierarchy 端点支持读/设 domain；管理台详情面板 6 选 1 + 清除；demo 已迁 v35 端到端验证。
- **评审后裁决（E）**：domain 属「文章级派生轴」，不应作为标签词表单值字段继续铺开——**不做**自动补猜回填、不做父级继承、不加深层级；字段保留但不推广。

## C. 未来新内容如何打标签（目标流程）

现状链路已具备：入队 → 顶部 150 复用表 → @tag 输出(thinking 关) → 别名/变体写侧解析 → @none → 兴趣(封闭)/AI(自由) 分流 → 两级层级+类型 → 屏蔽词跳过。
需要补的“面向未来的语义”：

### C1 新词治理闭环（推荐落地）
1. AI 模型仍可造新词（不强行禁止），但**新词 = 未审核状态**（tags.created_at / reviewed_at 已具备，v34）
2. 自动打标写入新词时**跳过“已屏蔽”**；写出时按惯例：先复用到现别名，再复用同 surface 变体，最后才建新词
3. **自动降级清理**：新词若满足 `仅1篇文章 && 超过90天 && 从未人工审核` → 后台删除（含其文章标签）——遏制长尾不回潮
4. UI：管理台"待处理"队列 = 人工 gate（确认/设父/设类型/屏蔽/合并）

### C2 层级/类型的“轻量自动建议”（可选，成本敏感）
- 不强求 LLM 每篇定级；改为**后台批量补猜**（复用 tidy 的聚类，但只跑“未审核新词”小批，按周）
- 或**规则初猜**：地名库/机构词（词表实体）命中 → 自动 entity+挂地区 topic；其余留给人工

### C3 内容入口的分层消费
- 列表/词云/搜索按当前主题树聚合展示（父级=子树，已有 v34 语义）；新内容进来自然落入既有父级，人工只见“未归类”的少数
- Meili 保持 keyword（含 CN/EN 同义词），Hybrid 是否引入取决于你对"语义/跨语言搜索"的需求（A1 一并评估）

### C4 指标与观测
- 标签健康仪表盘：词总数、未审核数、一次性占比、每周净增长、屏蔽命中率、别名新增
- 出现异常（某周净增 >阈值）→ 提醒开一轮 tidy 干跑

## E. 架构评审结论（2026-09-09 定）
对「标签系统 + L1-L5 分层」的整体评审（数据依据：35k 文章 / 4 tags·篇 / 10.9k AI 词其中 40% 仅 1-2 篇 / 树仅 63 个父节点、99% 词未入树）。裁决：

1. **层级定位**：层级是「浏览/聚合的可选视图」，不是数据模型的核心承诺。两级树（63 父节点）够用，**不再加深**（三层/多父会倍增治理成本）。
2. **domain 重新定性**：设计文档的单元是**文章**（domains 1-3 个 + confidence），我们实现成了**标签单值字段**——语义会被合并/别名搅动，且单值逼单域。将来若做领域聚合，domain 应是**文章级派生属性**（标签投票/LLM 补判，允许多选），与词汇治理解耦。
3. **L4 属性（风险/情绪/时效/影响力/政策类型）砍掉**：每篇 5 属性 + 置信度成本最高、时效强、个人 RSS 无消费方；即便要"情报简报"也只在命中的子集上按需算。
4. **L5 + gate 保留**：新词=提案→人工确认，与 review/suppression 同一条防线，方向正确。
5. **词库收敛单一事实源**：wordcloud 实体 JSON / meili synonyms 915 / entity tags 三处并存是事故源 → entity 并入 tags，wordcloud 现算，synonyms 由 aliases 派生。
6. **顺序重排**（见 D）：gate → C1 自动清理 + C4 指标 → 单一事实源 → B1；领域/属性全部后置到有消费场景为止。
